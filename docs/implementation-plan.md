## Phase 0：工程初始化 ✅

**目标**：建立一个能跑起来的、规范化的桌面工程骨架。

交付内容：

1. Git 仓库与 `.gitignore`。
2. pnpm monorepo：`apps/desktop` + `packages/{core,storage,agent,validation}`。
3. Tauri 2 + React 19 + TypeScript + Vite 工程。
4. Tailwind CSS v4（通过 `@tailwindcss/vite`，无需 config 文件）。
5. ESLint（typescript-eslint 类型感知规则）+ Prettier。
6. Vitest 测试框架与根配置。
7. 严格 TypeScript 配置（project references）。
8. `AGENTS.md`、`README.md`、`docs/` 四份文档。
9. 应用图标（Tauri bundle 所需全尺寸）。

验收结果：

- ✅ `pnpm dev:tauri` 能启动桌面窗口。
- ✅ `npx tsc -b tsconfig.json` EXIT 0。
- ✅ `npx vitest run` 可运行。
- ✅ `npx eslint . --max-warnings 0` EXIT 0。

**关键难点与解决**（详见 decisions.md）：

- pnpm 12 从 `pnpm-workspace.yaml` 读取 store 配置，而非 `.npmrc`。
- 工作区在 exFAT 卷上，Tauri build script 会因 macOS AppleDouble `._*` 文件崩溃，必须把 `CARGO_TARGET_DIR` 指向 APFS 路径。

## Phase 1：小说编辑器 MVP ✅

**目标**：用户创建小说后可以立即写作，所有内容真实落盘。

交付内容：

1. 三栏布局（文件树 / 编辑器 / Agent），侧栏可折叠、可拖拽调宽。
2. 小说项目创建与打开（目录选择器）。
3. 文件树：按 `chapters` / `characters` / `world` / `plot` 分组，章节按序号排序。
4. 章节新建（自动分配 `001.md` 序号）与打开。
5. Tiptap 富文本编辑 + Markdown 序列化往返。
6. 自动保存（900ms 防抖）、手动保存（⌘S）、保存状态提示。
7. 字数统计（中文按字符、英文按词）。
8. 外部修改检测与冲突提示（覆盖 / 重新载入）。
9. 基础搜索（⌘K 快速跳转，中文 bigram 检索）。
10. 深色 / 浅色主题。

验收结果：

- ✅ 创建《示例小说》后立即可写。
- ✅ 正文真实保存为 `chapters/001.md`。
- ✅ 关闭重开后内容完整（e2e 测试覆盖）。
- ✅ 连续打开保存不丢段落与标题（往返测试覆盖）。

**不包含**：富文本工具栏、图片、导出。第一轮只保证"能写、能存、不丢"。

## Phase 2：AI Agent 基础能力 ✅

**目标**：AI 能读项目、生成文件变更提案，作者确认后写入真实文件。

交付内容：

1. 模型配置界面（OpenAI 兼容 / DeepSeek / Moonshot / Ollama）。
2. API Key 存入系统钥匙串，Rust 侧代发请求。
3. Agent 聊天侧栏，流式回复。
4. 执行步骤可视化（分析 → 检索 → 生成 → 校验 → 提案）。
5. 工具调用协议（15 个工具，含参数 Zod 校验与结果校验）。
6. 文件读取 / 列表 / 搜索工具。
7. Change Proposal 系统：创建 / 存储 / 加载 / 提交 / 拒绝。
8. 提案卡片：逐文件差异预览（unified diff）、单项接受或拒绝、全部接受或拒绝。
9. 版本校验：提案绑定 `baseContentHash`，文件被外部修改则拒绝提交。
10. 提交前自动快照，失败可回滚。
11. 任务取消与失败重试。
12. 模型不支持工具调用时明确提示能力受限。

验收结果：

- ✅ 输入「创建第一章，描写示例主角回到白塔学院」→ 生成章节提案。
- ✅ 接受后章节出现在文件树、正文出现在编辑器。
- ✅ 文件真实保存为 `chapters/001.md`（e2e 测试断言磁盘内容）。

**明确未实现**：多轮工具调用的并行执行、跨文件 ChangeSet 的原子提交（当前为顺序写入 + 快照回滚）。

## Phase 3：角色卡生成 🚧

已交付首个可运行切片：多角色与有方向关系提案、来源表、局部字段更新、已确认字段保护、Mock 全链路测试。仍缺字段级确认、歧义候选、旧卡迁移及真实桌面人物生成验收，不能标记整阶段完成。

**目标**：一段自然语言生成完整角色卡，并区分"用户说的"和"AI 补的"。

计划任务：

1. 人设意图识别（Intent Parser）与实体提取（Canon Extractor）。
2. 复用 `packages/validation` 实现 `CharacterCardSchema` 运行时校验。
3. 分阶段工作流：Intent → Canon → Retriever → Consistency → Designer → Relationship → Validation → Preview → Commit。
4. 角色卡预览 UI（分字段展开，标注每个字段的来源状态）。
5. 角色设定文件自动创建（`characters/character-NNN.md`，YAML Frontmatter + 正文）。
6. 角色更新：只改受影响字段，不覆盖已确认设定。
7. 关系提案（`CharacterRelationship`，允许不对称）。
8. 一次生成多个相关角色。
9. 对话中持续微调（"让她性格更偏执"）。

验收标准：

- 输入两个角色的自然语言描述 → 生成两份完整但不过度臆造的角色卡。
- 展示两人潜在关系。
- 确认后创建对应文件。
- 追加「让室友的性格更易怒」→ 只修改受影响部分。

**依赖**：Phase 2 的 Proposal 与工具框架已就绪。

## Phase 4：世界观自动构建 🚧

按作者本轮要求，在 Phase 3 最小链路真实验收后开始。已实现并实测“三候选 → 作者选择 → 所选方向细化提案 → 审核写入”。已补齐非空主题约束、未确认草稿的八类区块局部更新和基于引用 / 文字匹配的关联影响审核。已确认设定冲突解决、完整语义分析与候选恢复仍未完成；不标记整阶段完成。

计划任务：

1. `WorldSettingSchema` 校验。
2. 基于已确认角色推导世界观方案。
3. 区分「指定已有世界观」与「原创世界观」两条路径。
4. 原创路径生成 2–3 个差异明显的候选方案（题材 / 时代 / 核心矛盾 / 人物适配理由）。
5. 用户选定后才细化组织、历史、规则、社会冲突。
6. 自动引用已有角色 ID。
7. 世界观持续变更与依赖分析。

验收标准：

- 仅提供两个角色卡 → 提出三个差异明显的世界观方案。
- 用户选定一个后才生成结构化世界观。
- 未经选择不得把多方案混入正式设定。

## Phase 5：剧情大纲与人物关系 ⬜

主线剧情提案、卷与章节大纲、伏笔列表、事件时间线、人物成长弧线、修改依赖分析。
**验收**：根据人物与世界观生成 20 章大纲，而不是直接写 20 章正文。

## Phase 6：自动上下文系统 ⬜

SQLite + FTS5 索引、中文检索、人物引用索引、上下文组装与 Token 预算、引用来源展示、索引重建。
**验收**：20 章项目里询问早期事件，能检索并引用正确章节；无检索结果时明确说不知道。

## Phase 7：AI 改稿与重构 ⬜

选区改稿、行内 Diff、跨文件 ChangeSet 原子提交、章节拆分合并、批量设定调整、自动快照与一键回滚。
**验收**：跨章修改人物设定时指出受影响位置并生成待审建议，不静默改写。

## Phase 8：连续性检查 ⬜

硬冲突（人物已死、认知越界、时空矛盾、规则违背）与软警告（语气突变、动机不足、伏笔遗忘）检测，附证据引用。
**验收**：定位人为植入的矛盾并给出原文引用。

## Phase 9：产品打磨与发布 ⬜

UI 一致性、快捷键、错误状态、自动恢复、导入导出、macOS 与 Windows 打包、使用文档。
**验收**：普通用户无需技术文档即可完成「新建小说 → 生成角色 → 构建世界观 → 创建大纲 → 写第一章 → 审核改稿」。
